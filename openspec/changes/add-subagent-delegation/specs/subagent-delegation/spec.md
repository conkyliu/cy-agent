# Spec: Sub-agent Multi-Agent Subtask Delegation

## Overview
Sub-agent delegation enables the primary agent to spawn an autonomous, isolated child session to execute focused exploration or analytical subtasks.

## Requirements

### Tool Definition (`delegate_task`)
- **Name**: `delegate_task`
- **Requires Approval**: `false` (read-only analytical delegation)
- **Parameters**:
  - `task` (`string`, required): Detailed task description for the sub-agent.
  - `goal` (`string`, required): Specific goal, output requirement, or conclusion criteria.
  - `context` (`string`, optional): Background context or path hints.

### Isolation & Execution
- The sub-agent MUST execute in an isolated `AgentSession` instance with its own message history.
- Intermediate tool calls and messages generated by the sub-agent MUST NOT be appended to the parent session's history.
- The sub-agent MUST be restricted to safe, read-only tools (`read_file`, `list_directory`, `search_files`, plus custom inspection tools). Dangerous tools (`write_file`, `run_shell`) and `delegate_task` itself MUST NOT be available to the child sub-agent.

### Safety & Guardrails
- **Max Depth Limit**: The system MUST enforce a maximum delegation depth (`maxDepth`, default 1). Sub-agents at maximum depth attempting to spawn another sub-agent MUST receive an error.
- **Iteration Budget**: The sub-agent MUST enforce a bounded iteration limit (`maxIterations`, default 10).
- **Cascading Abort**: When the parent session's `AbortSignal` is triggered, the child sub-agent MUST immediately abort execution.
